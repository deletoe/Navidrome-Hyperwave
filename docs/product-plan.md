# My Navidrome 5.6 产品计划

## 1. 产品定义

My Navidrome 5.6 是一个面向个人长期使用的 Navidrome Web 音乐客户端。它以桌面 Chrome 和手机 Chrome 为主要运行环境，覆盖连接、发现、浏览、搜索、播放、队列和收藏的完整日常闭环。

产品的核心辨识度是“视觉人格”：当前歌曲的曲风、内容类型和元数据不仅改变配色，也会切换整套桌面舞台，包括导航姿态、内容编排、卡片比例、播放器位置、队列形态、字体、多媒体背景和转场语言。视觉布局可以激进变化，但语义 DOM、键盘顺序、焦点节点和唯一的音频节点保持稳定，用户不会因为换曲丢失播放状态或操作对象。

## 2. 本版目标

首个本地可运行版本必须完成以下闭环：

1. 用户输入 Navidrome 地址和凭据，浏览器用 Subsonic token/salt 鉴权连接服务。
2. 首页独立加载最新、随机和常听专辑，并展示真实封面和可操作的曲风入口。
3. 用户可以打开专辑、艺术家和曲风，查看歌曲并执行播放、加入队列和收藏。
4. 搜索覆盖歌曲、专辑和艺术家；空结果、加载和失败都有明确状态。
5. 播放器支持播放/暂停、上一首/下一首、进度、音量/静音、随机、循环和清空队列。
6. 收藏操作同步到 Navidrome，并在独立收藏页、歌曲列表和当前播放区保持一致。
7. 当前歌曲驱动七套拥有独立布局、原创环境背景、前景装置和转场动画的视觉人格，并尊重系统的“减少动态效果”设置。
8. 宽屏允许七套人格重排为侧栏工作台、顶栏控制台、花园舞台、RPG 面板、地下演出、电影银幕或唱片室；手机仍使用稳定的底部导航、固定迷你播放器和可展开播放面板。
9. 高频操作使用统一图标语言：密集的播放、队列、收藏、关闭和 transport 控件以图标为主，低频或高风险操作保留“图标 + 短文字”，并始终提供可访问名称与足够触控面积。
10. 当前专辑封面在浏览器内提取主色、辅色和暗色，并按可调强度混入七套人格；取色失败时无提示打断地退回人格原色。
11. 用户可在频谱、粒子、混合和关闭四种 Web Audio 表现间切换；七套人格拥有不同的实时绘制策略，环境舞台与播放器内嵌舞台同步响应，播放器和唯一音频节点不因视觉切换而重挂。
12. 独立 Theme Studio 提供主题强度、封面响应、人格预览和曲风映射编辑；安全偏好保存在本机，认证 URL、封面字节和曲库元数据不会写入持久化配置。
13. 独立 Artists 入口展示完整歌手索引；选中歌手后同时提供其全部专辑和这些专辑中的完整歌曲集合，可整组播放或加入队列。

## 3. 用户故事

### 3.1 连接与会话

- 作为用户，我可以使用服务器地址、用户名和密码连接 Navidrome。
- 应用保存服务器地址和用户名，密码只保留在当前页面内存中。
- 连接成功后显示服务类型、版本和 OpenSubsonic 支持状态。
- 我可以主动断开，断开时音频停止、队列和会话数据清空。
- 网络失败时，错误文案能区分 URL、CORS、HTTP/HTTPS 混合内容、鉴权和服务端错误。

### 3.2 发现与浏览

- 首页展示最新专辑、随机专辑、常听专辑和曲风入口。
- 各首页分区独立加载；一个接口失败不能阻止其它内容显示。
- 专辑卡片使用稳定、懒加载的真实封面 URL，播放进度变化不能触发整页封面重复下载。
- 打开专辑后可以查看元数据和完整曲目，并一键播放全部或加入队列。
- 主导航可进入完整、按服务端索引分组的歌手库，并支持按歌手名即时筛选。
- 筛选词和目录滚动位置在进入歌手详情后保留；返回时恢复原上下文，新详情从顶部开始并把键盘焦点移到主区域。
- 搜索、收藏、歌曲行、专辑详情和当前播放区中的可识别歌手都可进入同一歌手详情。
- 打开歌手后先显示完整专辑列表，再以受限并发补齐各专辑曲目；个别专辑失败不阻止其余歌曲显示。
- 专辑歌曲按完成进度逐批出现；每个请求有 15 秒超时并真正中止底层网络传输，详情切换、断连和目录刷新也会取消旧请求。
- 歌手详情可一次播放或入队全部聚合歌曲；曲目按服务端专辑顺序和盘片顺序保持稳定，并按歌曲 ID 去重。
- 点击曲风会加载该曲风的歌曲列表。

### 3.3 搜索与收藏

- 搜索支持回车和按钮提交，并返回歌曲、专辑、艺术家三类结果。
- 查询为空时不发请求；无结果时显示可理解的空状态。
- 用户可以在歌曲行和当前播放区收藏或取消收藏。
- 收藏页展示服务端真实收藏歌曲；写入成功后立即乐观更新，再后台校准。

### 3.4 播放与队列

- 点击歌曲立即播放，并以当前列表作为播放队列。
- 用户可以追加歌曲或整张专辑、删除队列项、清空队列和跳转到指定队列项。
- 上一首、下一首、随机播放和关闭/全部/单曲循环具备确定行为。
- 清空队列、断开连接或删除最后一首时必须立即停止并卸载音频源。
- 播放开始时发送一次 scrobble；达到歌曲一半或 4 分钟中的较早值后提交播放记录。
- 用户主动播放或恢复时，有效音量以 smoothstep 包络在 320ms 内从静音升到用户设定；暂停时 UI 立即响应，声音在 240ms 内衰减后才暂停媒体元素。包络不改写音量滑杆，快速暂停/恢复会从当前响度平滑反向，静音、零音量和后台页面则立即停止。
- 浏览器 Media Session（可用时）展示当前歌曲并响应系统级播放控制。
- 不假定音频为 MP3；由浏览器按服务端媒体类型播放。

## 4. 视觉人格系统

| 人格 | 主要元数据线索 | 宽屏舞台 | 多媒体与转场 |
| --- | --- | --- | --- |
| Prism Archive | 无足够线索 | 三栏档案工作站、玻璃目录卡、右侧索引队列 | 棱镜穹顶图；折射面扫场 |
| Neon Circuit | electronic、techno、synth、EDM | 顶栏指挥台、密集终端曲目、右侧诊断播放器 | 无缝电路图；霓虹扫描 |
| Soft Bloom | pop、female vocal、mandopop、华语 | 顶部花园导航、全宽内容、底部悬浮播放台 | 透明花瓣图；径向绽放 |
| Pixel Quest | game、OST、8-bit、chiptune、video game | 8px RPG 三栏、库存卡、HUD 播放器 | 32 色像素砖；阶梯闭幕 |
| Riot Stage | rock、metal、punk、grunge | 左侧后台栏、非对称演出区、底部机架与歌单 | 地下舞台图；撕纸横扫 |
| Silver Screen | soundtrack、score、classical、orchestral | 顶部片头栏、居中银幕、底部 transport 与片尾队列 | 聚光舞台图；幕布开合 |
| Midnight Club | jazz、soul、blues、funk | 窄侧栏、唱片室内容、右侧转盘与演出单 | 深绿黄铜烟雾图；烟幕漂移 |

主题判定使用歌曲的 `genre`、`genres`、标题、专辑和艺术家文本，采用可测试的优先级规则。`VisualTheme.scene` 输出唯一的 `layout`、`transition`、资源路径、资源模式和显示/正文字体；`themeToCssVars` 统一输出图片、字体、颜色和分层动效时长。

七张环境图和七张 4:5 前景装置图均为本项目通过内置图片生成器创建的原创、无文字、无人物、无品牌素材。生成过程没有使用曲库截图、专辑封面、艺人身份、服务器信息或播放历史。交付资源统一去元数据并保留 CSS 渐变作为加载失败时的完整降级；Pixel 资源使用最近邻缩放维持硬边像素。

`HeroMedia` 是每个主要页面的前景媒体舞台：它把当前人格的装置图与最多三张实时 Navidrome 封面组合成可随曲风剧烈重排的稳定 DOM。Prism 使用光学展柜，Cyber 使用设备控制台，Bloom 使用花瓣轨道，Pixel 使用 RPG 神龛，Rock 使用撕纸演出拼贴，Cinematic 使用电影海报框，Lounge 使用唱片与黄铜拱门。首页、搜索、收藏、专辑、艺术家、曲风和连接页均能复用该舞台；曲目行与队列项另有 128px/96px 封面缩略图，图片不再只停留在页面背景。

所有新增前景图均为纯装饰：容器 `aria-hidden`，没有交互后代，图片使用空 `alt`。实时封面加载失败时退回程序化音乐占位；主题装置加载失败时隐藏故障节点，由底层渐变和其它封面继续完成构图。主题切换只替换资源与 CSS 构图，不重挂 `HeroMedia`、播放器或音频节点。

转场由唯一的 `ThemeBurst` 装饰层承担。它只包含不可聚焦、不可点击的 span，不拥有播放器状态；应用根、播放器和 `<audio>` 不以主题作为 key。控件反馈固定在约 150ms，抽屉约 280ms，七套主题转场各自在 600–900ms 内完成并自动卸载。系统请求减少动态效果时完全隐藏转场层并停止环境动画。

### 4.1 自适应视觉控制台

封面取色通过带既有 Subsonic 鉴权的 `getCoverArt` 请求读取小尺寸图片 Blob，再在 48×48 的离屏 Canvas 中量化。算法过滤透明、近黑和近白噪声，选出稳定的高权重主色与具备距离的辅色，并生成受限暗色。内存缓存只以 `coverArt` ID 为键，最多保留 64 项；不保存带 token 的 URL、图片字节或分析日志。请求可取消、结果按代次提交，快速切歌不会把旧封面颜色应用到新歌曲。

主题强度统一控制封面颜色混合比例、环境图、纹理、前景光晕、装置和可视化层的不透明度。强度或封面颜色变化只更新根 CSS 变量，不触发 `ThemeBurst`，也不重挂应用壳、播放器或音频元素。人格预览可以临时覆盖自动判定；选择 Automatic 后重新服从当前歌曲与曲风映射。

Theme Studio 是 Home、Artists、Search、Favorites 之外的第五个主入口。它展示当前封面、实时提取的三枚色样、0–100 强度滑杆、四种可视化模式、Automatic 加七套人格预览卡，以及由真实曲库曲风生成的可筛选映射表。曲风映射使用 NFKC 和空白归一化后的精确匹配，优先级高于内置正则；选择 Automatic 会删除覆盖项。持久化数据严格限制为版本、强度、布尔开关、可视化枚举和最多 250 条曲风到人格的白名单映射。

实时音频层使用两块由同一 analyser 与同一人格策略驱动的稳定装饰 Canvas：全屏环境舞台位于背景与应用壳之间，播放器舞台位于 Now Playing 表面内部，因此频谱不会再只藏在半透明页面背景中。Prism、Cyber、Bloom、Pixel、Rock、Cinematic 和 Lounge 分别绘制旋转棱镜万花筒、透视霓虹控制台、双轨花瓣、像素阶梯电平、三重撕裂波、宽银幕光幕和唱片黄铜环；七套粒子的发射位置、轨迹和形状也互不相同。Spectrum、Particles 与 Hybrid 决定绘制组合。环境舞台限制为 30 FPS、180 万 backing pixels 和 1.25× DPR，播放器舞台限制为 45 FPS、50 万 backing pixels 和 1.5× DPR；两者在相同浏览器帧内复用一次 analyser 采样，页面隐藏时取消 RAF。单帧最多使用 96 个波形采样点和 80 个粒子，关闭、暂停或 analyser 尚未 ready 时立即清空并停止绘制。

Web Audio 图只在用户播放或主动切换可视化时创建，且每个实际 `<audio>` 最多调用一次 `createMediaElementSource`。链路固定为 media source → analyser → destination；创建、恢复或 CORS 分析失败不会阻断普通播放，并在 Studio 与播放器中显示状态。首次 `AudioContext.resume()` 若长时间不返回，会在尚未接管媒体元素时安全放弃并保留 `waiting`，下一次真实播放手势可以重新创建；已连接 context 的 suspended/interrupted/closed 状态也会实时同步。快速切歌通过播放代次阻止旧 `play()` rejection 覆盖新歌曲的播放和频谱状态。播放进度只在跨越可见整秒时发布 React 状态，seek、ended 和 scrobble 仍使用真实时间即时处理，避免整页曲库随高频 `timeupdate` 重绘。播放可视化实际 ready 期间，大面积表面停止 backdrop blur 重采样，强滤镜只保留在较小的播放器舞台；批量卡片转场不再同时动画阴影和位移，以降低主题切换时的整页合成负担。本轮按用户选择，新的实时频谱/粒子层不根据 `prefers-reduced-motion` 自动降级；既有主题转场和环境动画的减少动态效果行为保持不变。

## 5. 响应式产品形态

### 桌面（1180px 及以上）

- Prism、Pixel、Lounge 使用比例不同的三栏舞台。
- Cyber 使用横向顶栏和贯穿全高的右侧播放控制台。
- Bloom 与 Cinematic 使用顶部导航、全宽内容和底部播放/队列 transport。
- Rock 使用左侧后台栏、主舞台和底部机架式播放/队列。
- 所有变化只用顶层 grid area，不使用会破坏键盘顺序的 `order` 或反向 flex。

### 平板（768px–1179px）

- 左侧导航收窄，中间内容占主区域。
- 队列变为从右侧打开的抽屉；播放器固定在底部。
- 各人格仍保留背景、字体、英雄区、卡片比例、边框和色彩语言，但不强行套用宽屏重排。

### 手机（767px 及以下）

- 顶部只显示品牌、当前页面和连接状态，不常驻完整连接表单。
- 底部为固定的 Home、Artists、Search、Favorites、Studio 五入口导航。
- 当前有歌曲时，导航上方出现带内嵌实时频谱舞台的固定迷你播放器。
- 点击迷你播放器打开全屏播放面板；队列在同一面板中切换，Off、Spectrum、Particles、Hybrid 四个模式保持 44px 触控区并可直接选择。
- 处理 `safe-area-inset-bottom`，页面不得横向溢出。
- 七套人格保留各自的前景构图，媒体舞台压缩为约 10–12rem 高并减少第三张封面的拥挤；降低环境背景不透明度并停用高成本持续动画，真实专辑封面在 Pixel 人格中仍保持清晰插值。

## 6. 控件与图标语言

- 统一使用 Lucide 线性图标，并通过 `AppIcon` 维护播放、队列、收藏、导航、加载和反馈动作的语义映射。
- 曲目行的播放、加入队列和收藏，播放器的 transport、静音、展开与队列入口，以及关闭、移除等密集操作采用纯图标按钮。
- 连接、断开、返回、搜索、重试、刷新、整张播放/入队等需要更强确认的操作采用“图标 + 短文字”，避免只靠陌生图形表达意图。
- 纯图标按钮必须保留 `aria-label` 和悬停提示；SVG 自身只作装饰，不重复进入辅助技术的可访问名称。
- 手机端所有可见操作至少为 44×44px；状态型控件同时使用图标形态、颜色或透明度表达，不只依赖文字。

## 7. 可靠性与安全

- 不在源码、构建产物或持久化存储中写入明文密码/API key。
- 密码模式使用每次会话稳定的随机 salt/token URL，避免 React 重绘导致封面和音频 URL 改变。
- 列表字段必须兼容 Navidrome 用空对象省略数组的返回形式。
- 资料库加载使用独立请求/部分成功策略，并支持单区重试。
- 当前本地 HTTP 页面直连当前 HTTP Navidrome 服务；未来若页面部署到 HTTPS，需要 HTTPS API 或同源代理，避免混合内容阻止。
- 页面具备清晰焦点、键盘可操作按钮、语义化标签、足够对比度和 `prefers-reduced-motion` 降级。
- 主题转场永不重挂应用树或音频节点；快速切歌时页面最多存在一个装饰转场层。
- 生成图片和重复封面拼贴均为纯装饰资源，没有 alt 文本表面或交互后代；图片失败时程序化渐变与音乐占位仍可独立构成页面。
- 封面分析请求省略 cookie 和 referrer，限制响应类型与 5MB 大小；所有错误文案不得包含认证查询、用户名、密码、token 或原始 URL。
- Web Audio 创建失败、被浏览器拦截或跨域不可分析时只能关闭实时绘制，不得让媒体元素静音、停止或失去普通播放路径。
- 视觉偏好只保存经过白名单清洗的安全字段；封面 URL、歌曲 ID、图片数据、音频帧和服务器凭据不进入 localStorage。

## 8. 验收标准

- `npm test -- --run` 全部通过，至少覆盖鉴权、响应解析、视觉人格、队列、格式化和应用壳。
- `npm run build` 无 TypeScript 或 Vite 错误。
- 从 `http://127.0.0.1:5173` 在真实 Chrome 中连接测试 Navidrome 成功。
- 首页至少展示两个非空专辑区、真实封面和真实曲风数据。
- 搜索能返回真实歌曲/专辑/艺术家；专辑、艺术家和曲风入口可继续导航。
- 对真实音频 URL 的 Range 请求返回 `206`，播放器 UI 可以进入当前歌曲状态。
- 1440×900 下七套宽屏舞台均与视口等宽、没有横向溢出，底部 transport 不裁切播放或队列控件。
- 390×844 与 360×800 下没有横向溢出，底部导航和迷你播放器固定可见，所有可见按钮至少 44px 高。
- 从电子、游戏/像素、摇滚、流行、古典、爵士等真实元数据歌曲切换时，`data-theme`、`data-layout`、背景资源、顶层 grid、播放器和队列同时变化。
- 主题变化前后的 `.app`、`.app-shell`、`.player-dock`、`audio` 和已聚焦控件必须保持同一 DOM 身份；转场层始终只有一个。
- 七套人格各自加载唯一的前景装置资源；主要页面只存在一个稳定的 `.hero-media`，最多组合三张不重复的实时封面。
- 曲风歌曲列表和播放队列中的封面分别请求 128px 与 96px 版本；装饰图片没有非空 `alt`、没有破图且不引入额外可聚焦元素。
- 清空队列和断开连接后，音频停止且不再保留媒体源。
- 纯图标按钮不存在空的可访问名称；390×844 下可见图标按钮没有小于 44×44px 的触控区。
- 播放带封面的真实歌曲后，Studio 显示三枚有效十六进制色样，根节点的主题主色和辅色相对人格默认值发生变化；关闭封面响应后立即恢复默认人格配色。
- 主题强度从 0 调到 100 时，运行时强度和分层不透明度变量同步变化，但 `.app-shell`、`.player-dock`、`audio` 和当前焦点节点身份不变，也不额外触发主题转场。
- 每个真实曲风可映射到任意七套人格并恢复 Automatic；精确映射优先于默认曲风规则，刷新后安全映射仍存在。
- Spectrum、Particles、Hybrid 和 Off 四种模式可从 Studio 或播放器切换；环境与播放器 Canvas 保持稳定身份，同一个音频元素最多创建一个 MediaElementSource，关闭可视化不关闭 AudioContext、不拆连接也不影响继续播放。
- 120Hz RAF 输入下环境舞台不超过 30 次绘制/秒，播放器舞台不超过 45 次；Canvas backing pixels 不得超过各自预算，相同 RAF timestamp 只读取一次 analyser，页面隐藏后不得继续排队绘制。
- 同一显示秒内的连续 `timeupdate` 不重复发布进度 React 状态，但 seek、曲末和跨越 scrobble 阈值仍立即生效。
- 播放渐入从零开始并精确落在当前用户音量；暂停渐出完成前媒体元素仍在播放，完成后只暂停一次。快速反向、切歌、reset、错误和卸载必须取消旧包络，旧 timer 或旧 `play()` Promise 不得误暂停新播放。
- 首次 AudioContext 恢复永久 pending 后，下一次用户手势仍能重试并进入 ready；context 离开 running 时状态不得误报 ready；旧曲延迟到达的 play rejection 不得停止新曲或清空新曲频谱。
- `getArtists` 的两层索引可兼容单对象、数组和空返回；进入歌手时先显示专辑，再以最多五个可中止的并发请求渐进聚合完整歌曲，旧请求、超时、断连和局部失败不会污染当前详情或继续占用网络传输。
- 1280×720 与 390×844 下 Artists 和 Studio 均无横向溢出，五入口导航可见可达；两块 Canvas 均只作装饰、不可点击、各自只有一个稳定实例，移动端新增模式控件不小于 44×44px。

## 9. 明确不在本版范围

- 播放列表创建/协作编辑。
- 歌词同步、评论和社交功能。
- Service Worker 离线缓存和下载。
- 多账号、家庭权限管理和服务端配置。
- AI 曲风分析和运行时自动生成图片。当前十四张项目内置的静态原创环境/前景主题素材、浏览器内封面取色与 Web Audio 分析属于本版交付物。

这些能力可以在当前 API、播放器和主题边界上增量加入，不影响本版日常主流程的完整性。
