# My Navidrome 5.6 产品计划

## 1. 产品定义

My Navidrome 5.6 是一个面向个人长期使用的 Navidrome Web 音乐客户端。它以桌面 Chrome 和手机 Chrome 为主要运行环境，覆盖连接、发现、浏览、搜索、播放、队列和收藏的完整日常闭环。

产品的核心辨识度是“视觉人格”：当前歌曲的曲风、内容类型和元数据不仅改变配色，也会改变背景语汇、字体气质、卡片轮廓、控件形态、信息密度和动效节奏。变化要明显，但不改变核心控件的位置和语义，确保熟悉播放器的用户不需要重新学习。

## 2. 本版目标

首个本地可运行版本必须完成以下闭环：

1. 用户输入 Navidrome 地址和凭据，浏览器用 Subsonic token/salt 鉴权连接服务。
2. 首页独立加载最新、随机和常听专辑，并展示真实封面和可操作的曲风入口。
3. 用户可以打开专辑、艺术家和曲风，查看歌曲并执行播放、加入队列和收藏。
4. 搜索覆盖歌曲、专辑和艺术家；空结果、加载和失败都有明确状态。
5. 播放器支持播放/暂停、上一首/下一首、进度、音量/静音、随机、循环和清空队列。
6. 收藏操作同步到 Navidrome，并在独立收藏页、歌曲列表和当前播放区保持一致。
7. 当前歌曲驱动七套差异明显的视觉人格，并尊重系统的“减少动态效果”设置。
8. 桌面使用三层工作台布局；手机使用底部导航、固定迷你播放器和可展开播放面板，而不是缩小桌面布局。

## 3. 用户故事

### 3.1 连接与会话

- 作为用户，我可以使用服务器地址、用户名和密码连接 Navidrome。
- 应用保存服务器地址和用户名，密码只保留在当前页面内存中。
- 连接成功后显示服务类型、版本和 OpenSubsonic 支持状态。
- 我可以主动断开，断开时音频停止、队列和会话数据清空。
- 网络失败时，错误文案能区分 URL、CORS、HTTP/HTTPS 混合内容、鉴权和服务端错误。

### 3.2 发现与浏览

- 首页展示最新专辑、随机专辑、常听专辑和曲风入口。
- 各首页分区独立加载；一个接口失败不能阻止其它内容显示。
- 专辑卡片使用稳定、懒加载的真实封面 URL，播放进度变化不能触发整页封面重复下载。
- 打开专辑后可以查看元数据和完整曲目，并一键播放全部或加入队列。
- 搜索到的艺术家可以打开详情并浏览其专辑。
- 点击曲风会加载该曲风的歌曲列表。

### 3.3 搜索与收藏

- 搜索支持回车和按钮提交，并返回歌曲、专辑、艺术家三类结果。
- 查询为空时不发请求；无结果时显示可理解的空状态。
- 用户可以在歌曲行和当前播放区收藏或取消收藏。
- 收藏页展示服务端真实收藏歌曲；写入成功后立即乐观更新，再后台校准。

### 3.4 播放与队列

- 点击歌曲立即播放，并以当前列表作为播放队列。
- 用户可以追加歌曲或整张专辑、删除队列项、清空队列和跳转到指定队列项。
- 上一首、下一首、随机播放和关闭/全部/单曲循环具备确定行为。
- 清空队列、断开连接或删除最后一首时必须立即停止并卸载音频源。
- 播放开始时发送一次 scrobble；达到歌曲一半或 4 分钟中的较早值后提交播放记录。
- 浏览器 Media Session（可用时）展示当前歌曲并响应系统级播放控制。
- 不假定音频为 MP3；由浏览器按服务端媒体类型播放。

## 4. 视觉人格系统

| 人格 | 主要元数据线索 | 视觉语言 |
| --- | --- | --- |
| Neon Circuit | electronic、techno、synth、EDM | 霓虹网格、锐角、单色数字字体、快速脉冲 |
| Soft Bloom | pop、female vocal、mandopop、华语 | 明亮柔光、花瓣光斑、圆润卡片、轻缓漂浮 |
| Pixel Quest | game、OST、8-bit、chiptune、video game | 像素边框、扫描线、硬阴影、阶梯式动效 |
| Riot Stage | rock、metal、punk、grunge | 撕裂斜纹、粗体大写、硬边卡片、舞台闪光 |
| Silver Screen | soundtrack、score、classical、orchestral | 电影幕布、衬线标题、宽留白、聚光渐变 |
| Midnight Club | jazz、soul、blues、funk | 深色酒廊、黄铜高光、细线框、慢节奏烟雾 |
| Prism Archive | 无足够线索 | 冷静的棱镜层次、清晰阅读、平衡密度 |

主题判定使用歌曲的 `genre`、`genres`、标题、专辑和艺术家文本，采用可测试的优先级规则。主题 schema 同时输出颜色、字体类别、圆角/边框、密度、纹理和动效强度。视觉变化不得降低正文对比度、隐藏焦点状态或移动主要播放控件。

## 5. 响应式产品形态

### 桌面（1180px 及以上）

- 左侧固定导航和连接状态。
- 中间为可滚动内容舞台。
- 右侧为当前播放和队列，内容滚动不影响播放控制。

### 平板（768px–1179px）

- 左侧导航收窄，中间内容占主区域。
- 队列变为从右侧打开的抽屉；播放器固定在底部。

### 手机（767px 及以下）

- 顶部只显示品牌、当前页面和连接状态，不常驻完整连接表单。
- 底部为固定的 Home、Search、Favorites 导航。
- 当前有歌曲时，导航上方出现固定迷你播放器。
- 点击迷你播放器打开全屏播放面板；队列在同一面板中切换。
- 处理 `safe-area-inset-bottom`，页面不得横向溢出。

## 6. 可靠性与安全

- 不在源码、构建产物或持久化存储中写入明文密码/API key。
- 密码模式使用每次会话稳定的随机 salt/token URL，避免 React 重绘导致封面和音频 URL 改变。
- 列表字段必须兼容 Navidrome 用空对象省略数组的返回形式。
- 资料库加载使用独立请求/部分成功策略，并支持单区重试。
- 当前本地 HTTP 页面直连当前 HTTP Navidrome 服务；未来若页面部署到 HTTPS，需要 HTTPS API 或同源代理，避免混合内容阻止。
- 页面具备清晰焦点、键盘可操作按钮、语义化标签、足够对比度和 `prefers-reduced-motion` 降级。

## 7. 验收标准

- `npm test -- --run` 全部通过，至少覆盖鉴权、响应解析、视觉人格、队列、格式化和应用壳。
- `npm run build` 无 TypeScript 或 Vite 错误。
- 从 `http://127.0.0.1:5173` 在真实 Chrome 中连接测试 Navidrome 成功。
- 首页至少展示两个非空专辑区、真实封面和真实曲风数据。
- 搜索能返回真实歌曲/专辑/艺术家；专辑、艺术家和曲风入口可继续导航。
- 对真实音频 URL 的 Range 请求返回 `206`，播放器 UI 可以进入当前歌曲状态。
- 桌面宽度下三层布局成立；手机宽度下无横向溢出，底部导航和迷你播放器固定可见。
- 从电子、游戏/像素、摇滚等不同元数据歌曲切换时，`data-theme` 和多个视觉层次明显变化。
- 清空队列和断开连接后，音频停止且不再保留媒体源。

## 8. 明确不在本版范围

- 播放列表创建/协作编辑。
- 歌词同步、评论和社交功能。
- Service Worker 离线缓存和下载。
- 多账号、家庭权限管理和服务端配置。
- 音频可视化 FFT、AI 曲风分析和自动生成图片。

这些能力可以在当前 API、播放器和主题边界上增量加入，不影响本版日常主流程的完整性。
