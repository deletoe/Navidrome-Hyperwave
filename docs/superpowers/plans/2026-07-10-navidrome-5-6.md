# My Navidrome 5.6 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and locally run a complete, responsive Navidrome SPA covering connection, discovery, entity browsing, search, playback, queue, favorites, and metadata-driven visual personalities.

**Architecture:** A typed Subsonic/OpenSubsonic client is the only network boundary; pure queue and theme modules hold deterministic domain rules; React hooks own session data and the singleton audio lifecycle; focused components render desktop and mobile application shells. The browser connects directly to the verified local Navidrome server, while transport construction stays isolated for a future proxy.

**Tech Stack:** React 19, TypeScript strict mode, Vite, Vitest, Testing Library, SparkMD5, Lucide React, browser HTMLAudioElement and Media Session APIs.

## Global Constraints

- The app is a browser SPA and must run at `http://127.0.0.1:5173`.
- Desktop Chrome and mobile Chrome are separate layout contracts; compact is `<768px`, medium is `768–1179px`, and wide is `>=1180px`.
- Credentials from `docs/requirements.md` may be used for live tests but must never be copied into source, generated docs, build output, localStorage, or logs.
- Password authentication uses Subsonic `u`, `t`, `s`, `v=1.16.1`, `c=my-navidrome-5-6`, and `f=json`, with `t=md5(password + salt)`.
- Empty Navidrome result objects must normalize missing list fields to `[]`.
- A visual personality changes at least palette, typography, surface geometry, texture, and motion; `prefers-reduced-motion` removes continuous/positional motion.
- Clearing the queue, removing its last current track, or disconnecting must synchronously pause audio and remove its source.
- The workspace has no Git repository and contains a plaintext test credential in the user-authored requirements, so implementation tasks end in verified checkpoints rather than creating commits.
